# Avir 9/10 Production Upgrade — Initial Codebase & UI Audit

**Date:** 2026-11-22  
**Auditor:** Principal Frontend & Data-Integrity Engineer  
**Status:** Audit Complete — Phase 0

---

## 1. Executive Summary

This comprehensive audit of the Avir repository (`https://github.com/XiaoArnav/avir`) evaluates data integrity, provenance, scientific correctness, architectural resilience, performance, security, and accessibility.

While Avir features strong domain modeling (Corsi-Rosenthal calculations, Berkeley Earth particulate equivalence, custom city architectural skylines, and a dual-theme system), the audit identified critical data-integrity flaws, synthetic fallback behaviors, security vulnerabilities, and client-side secret exposure that prevent it from being a trustworthy 9/10 production product.

Every issue is categorized below by severity, root cause, planned correction, and verification method.

---

## 2. Critical Findings Matrix (Prioritized)

### CRIT-01: Synthetic Multi-Source Consensus via Single-Source Multipliers
* **Severity:** Critical (Data Integrity & Trust)
* **File:** `src/domain/advanced-air-math.ts` (`buildMultiSourceFeeds`, `calculateMultiSourceConsensus`), `src/components/MultiSourceInspectorModal.tsx`
* **Root Cause:** The 5 "independent feeds" (Copernicus CAMS, NOAA GFS, CPCB NAQI, US EPA, Surface Mesh) are artificially generated by multiplying a single Open-Meteo PM2.5 / AQI reading by arbitrary fractions (`* 0.96`, `* 1.04`, `* 1.08`). This presents synthetic numbers as independent agreement.
* **Planned Correction:** Eliminate synthetic multipliers and fabricated agreement percentages. Transform the data model to reflect genuine provider provenance. For the primary atmospheric stream, transparently disclose Open-Meteo's ECMWF & NOAA GFS numerical chemistry models. For comparisons, only display genuinely queried, distinct data sources or mark them as unavailable.
* **Verification:** Vitest unit test confirming no synthetic scaling functions exist; runtime inspection confirming displayed feeds match genuine upstream data.

---

### CRIT-02: Hardcoded Numerical Fallbacks on API Failure
* **Severity:** Critical (Rule 1 & Rule 3 Violation)
* **File:** `src/services/telemetry-service.ts` (`fetchLiveAtmosphericMetrics`)
* **Root Cause:** When the Open-Meteo Air Quality or Weather API fails or times out, the `catch` block synthesizes a full simulated state (`fallbackPM25 = 165.0`, `fallbackUsAqi = 235`, `pm10 = 210.0`) and generates a synthetic 24-hour hourly array with `sourceAttribution: 'Offline Regional Benchmark (Simulated Station Fallback)'`.
* **Planned Correction:** Replace silent synthetic fallbacks with an explicit typed telemetry result union:
  - `Loading`
  - `Success` (with genuine observed/modeled readings, timestamps, and freshness)
  - `Stale` (cached data with original timestamp and visual stale indicator)
  - `Unavailable` / `Error` (transparent error state with user retry button)
  Never display an invented number when an API call fails.
* **Verification:** Vitest test simulating API rejection; assert that AQI and PM2.5 are null/undefined and the UI displays an honest unavailable error state.

### CRIT-03: Synthetic City Ranking Generator in World Explorer
* **Severity:** Critical (Rule 1 & Rule 2 Violation)
* **File:** `src/services/world-telemetry-service.ts` (`fetchAllWorldCities`, `searchAndFetchGlobalCity`)
* **Root Cause:** When the batch query fails, `fetchAllWorldCities` uses an offline formula:
  `mockAqi = 265 - idx * 5`, `mockPm25 = 215.0 - idx * 4`. When dynamic search fails, it assigns `usAqi: 75, pm25: 22`.
* **Planned Correction:** Remove the synthetic generator completely. Use live batch Open-Meteo queries for the curated tracked cities list. If a batch query fails, return a clear error state or partial results where only verified cities are shown. Rename feature accurately to **"Air Quality Across Tracked Cities"** instead of claiming complete worldwide coverage.
* **Verification:** Unit test asserting failure to fetch batch cities yields an empty/error list, never synthetic ranks.

### CRIT-04: Client-Side Secret Exposure & Unprotected Gemini API Calls
* **Severity:** High (Security & Architecture)
* **File:** `src/services/ai-assistant-service.ts` (`generateAirQualityPlan`)
* **Root Cause:** Gemini API requests are made directly from the client browser using `fetch('https://generativelanguage.googleapis.com/...key=' + apiKey)`. This exposes API keys in URL query strings visible in browser developer tools, web logs, and referrer headers.
* **Planned Correction:** Move all AI plan generation to a secure Next.js App Router API route (`/api/ai/plan`). The client sends only sanitized context (city, verified metrics, profile, room size). The server accesses `process.env.GEMINI_API_KEY`, validates input, validates model output schema, and falls back to deterministic local air-math calculations if AI is unavailable or no key is configured.
* **Verification:** Integration test verifying client never contacts `generativelanguage.googleapis.com` directly; verify server route rejects invalid schemas.

### CRIT-05: Missing AbortController & Race Conditions in City Switching
* **Severity:** High (Data Correctness & UI Glitches)
* **File:** `src/app/page.tsx`, `src/services/telemetry-service.ts`
* **Root Cause:** When switching between cities rapidly, asynchronous network requests run concurrently without request cancellation (`AbortController`). A slower response for "Delhi" can resolve after a faster response for "Mumbai", displaying Delhi's telemetry under Mumbai's header.
* **Planned Correction:** Implement request cancellation with `AbortController` and location-request ID tagging. When a user selects a new city, abort in-flight requests for previous coordinates. Ensure state updates match the active city ID.
* **Verification:** Concurrency test verifying rapid switching (A -> B -> C) always renders city C's telemetry.

### CRIT-06: Timezone Contamination in Hourly Forecast
* **Severity:** Medium-High (Scientific Correctness)
* **File:** `src/services/telemetry-service.ts` (`hourlyForecast.map`), `src/components/DiurnalForecastTimeline.tsx`
* **Root Cause:** Open-Meteo returns local ISO date strings (e.g. `2026-11-22T14:00`). When parsed with `new Date(timeStr).getHours()`, JavaScript converts the string into the client browser's local timezone. A user in New York inspecting Tokyo sees New York hours instead of Tokyo local time.
* **Planned Correction:** Parse hour values directly from the provider's location-local ISO string (`timeStr.split('T')[1].slice(0, 2)`) or use `Intl.DateTimeFormat` with the provider's `timezone` field.
* **Verification:** Unit test verifying Tokyo forecast timestamps preserve local Tokyo time regardless of runner timezone.

### CRIT-07: CAQM GRAP Regulatory Legal Claim Inferred Solely from AQI
* **Severity:** Medium (Regulatory & Scientific Integrity)
* **File:** `src/domain/air-math.ts` (`getGrapStage`), `src/components/AtmosphereHero.tsx`
* **Root Cause:** The app declares "Stage III: Ban on non-essential construction, BS-III vehicle restrictions" purely because US AQI is > 400. GRAP stages are legal regulatory notifications issued by the Commission for Air Quality Management (CAQM) based on multi-day forecasts and committee orders, not an automatic instant trigger.
* **Planned Correction:** Clarify the badge as an **"Action Threshold Advisory"** (based on CAQM threshold criteria) with an explicit note: "Advisory guidance based on CAQM threshold criteria. Legal enforcement depends on official district administration orders."
* **Verification:** Verify component renders advisory note and does not claim legal decree.

---

### CRIT-08: Unverified Biological Protection Claims
* **Severity:** Medium (Toxicological Honesty)
* **File:** `src/components/ImpactScorecard.tsx`, `src/services/ai-assistant-service.ts`
* **Root Cause:** Phrases like "Deep alveolar mass prevented from entering pulmonary capillaries" and fixed "14.5 kg weekly carbon saved" make absolute clinical and environmental claims for all users.
* **Planned Correction:** Clearly mark all derived values as **"Modeled Inhalation Estimates"** based on standard physical ventilation assumptions ($0.8\text{ m}^3/\text{hr}$ walking, $2.8\text{ m}^3/\text{hr}$ cardio, $22\ \mu\text{g/m}^3 \approx 1\text{ cig/day}$ Berkeley Earth model). Remove arbitrary fixed carbon savings.
* **Verification:** Verify UI states explicit methodology and assumptions.

### CRIT-09: Corsi-Rosenthal Box Fixed Retail Pricing
* **Severity:** Low-Medium (Product Honesty)
* **File:** `src/components/IAQStudio.tsx`, `src/domain/air-math.ts`
* **Root Cause:** Component lists exact INR prices (Fan: ₹1,400, Filters: ₹1,200) as though they were live catalog prices.
* **Planned Correction:** Label component prices as "Estimated DIY Material Costs (Local Market Reference)" and allow users to inspect the breakdown or customize filter count.
* **Verification:** Verify text clarity in IAQ studio.

---

### CRIT-10: Accessibility (WCAG 2.2 AA Compliance Gaps)
* **Severity:** Medium (Accessibility & UX)
* **File:** Modal dialogs, icon buttons, slider controls across components.
* **Root Cause:** Some buttons lack accessible names; modal dialogs need strict keyboard focus trapping (`focus-trap` / Escape key listener); color contrast in light mode needs verification across severity badges.
* **Planned Correction:** Implement focus trapping, Esc key dismissal, accessible dialog attributes (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`), verify 4.5:1 text contrast in both light and dark themes.
* **Verification:** Vitest accessibility test suite checking dialog roles, escape handlers, and aria attributes.
